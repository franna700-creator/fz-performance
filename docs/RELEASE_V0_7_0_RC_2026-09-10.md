# FZ Performance v0.7.0 Release Candidate

Date prepared: 10 Sep 2026
Status: PREPARED OFF-VERCEL — NOT YET DEPLOYED

## Release objective

Make the consolidated FZ Performance operating system **truthfully dynamic, observable and deployment-efficient** before Tranche 4.2 introduces automatic recommendation recomputation.

## Included

### Dynamic physiology
- persisted wellness paints immediately;
- explicit Garmin source check on initial load;
- 5-minute source cadence while visible;
- focus / visibility / online wake-up checks with a 2-minute client throttle;
- manual `Refresh Garmin` remains force-refresh;
- successful persistence immediately triggers canonical reread;
- Body Battery, Stress, Heart Rate and Respiration intraday scrub graphs retained;
- source timestamp, persistence timestamp and freshness remain visible.

### Dynamic training
- persisted Training Memory paints first;
- 5-minute Tredict/Garmin source reconciliation while visible;
- focus / visibility / online wake-up checks;
- manual `Sync workouts`;
- successful source response must be structurally valid before being treated as synced;
- successful persistence immediately triggers canonical reread of downstream views.

### Dynamic downstream views
The clean app already rereads `/api/runtime-state`, wellness, training memory, Trends and SYSTEM every 5 minutes while visible and on focus/visibility/online wake-up. The source controllers now explicitly invalidate those canonical views after persistence, reducing lag between source arrival and downstream UI change.

### Tranche 4.1 observability
- no new serverless route;
- SYSTEM reuses `/api/system/status` materiality data;
- read-only Adaptive Intelligence panel shows engine version, latest materiality, state-update request, recommendation recompute request/block state and reason codes;
- 4.2 boundary remains explicit.

### Release reliability
- automatic Vercel Git deployments disabled;
- training/trends/system API cache headers explicitly no-store;
- release identity aligned to v0.7.0 RC;
- production smoke rewritten around dynamic invariants rather than moving exact current totals;
- documentation updated to Neon-primary / immutable-state-fallback architecture.

## Explicitly excluded

- no Tranche 4.2 recommendation recomputation;
- no new readiness algorithm;
- no new Vercel project;
- no new normal state-deployment mechanism;
- no dependency upgrade merely to silence the current `url.parse()` deprecation warning.

## Deployment target

One deliberate pinned Preview → browser/runtime acceptance → one production release.
